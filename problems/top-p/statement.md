# 逐行 Top-P 核筛选

输入是一个按行主序连续存放的 `rows x cols` 单精度概率矩阵。每行元素都是有限非负数，且行和为 1。给定阈值 `p`，请在 GPU 上对每行独立完成 Top-P（nucleus，核采样）筛选。

对一行概率按降序排列，记为 `q[0] >= q[1] >= ... >= q[cols - 1]`。当 `p < 1` 时，保留能使累积概率达到 `p` 的最短前缀：

```text
count = min { k | 1 <= k <= cols,
                  q[0] + ... + q[k - 1] >= p }

output[row, rank] = q[rank]    if rank < count
                    +0.0       otherwise
counts[row] = count
```

当 `p == 1` 时，题目明确要求保留该行的全部 `cols` 个元素，即 `counts[row] == cols`。

## 输出布局

`output` 不保持输入中的原列位置，而是按概率降序的排名位置存放。保留前缀中的概率值必须与输入值完全相同，不需要再归一化；未保留的尾部必须写成精确的正零 `+0.0`。如果一行中存在相同概率，它们之间的相对顺序不受限制。

## 实现约束

只实现平台约定的 `solve`，不要提供独立程序入口。`probabilities`、`output` 和 `counts` 都是 GPU 缓冲区，且互不重叠。`probabilities` 为只读，调用后内容必须保持不变。每次调用都必须覆盖全部输出，不得依赖 `output` 或 `counts` 原有内容。

`rows` 至少为 1、至多为 65,536；`cols` 至少为 1、至多为 1,024；元素总数不超过 4,194,304。`p` 满足 `0 < p <= 1`。

平台预先分配输入和输出，并控制执行 stream。实现必须把工作提交到平台选择的当前 stream，写入已有的 `output` 和 `counts`，且不应在返回前执行设备级同步。所选语言的确切函数签名和调用规则见题面末尾的语言说明。

## 正确性与性能

公开样例包含单元素行和列数非 2 的幂的矩阵。完整验证还会覆盖非规整尺寸、不同概率分布、`p == 1`、最大行数、最大行宽和约 400 万元素的输入。测试数据会使 `p` 与相邻前缀和保持足够间隔，避免并行扫描的正常浮点舍入改变应保留元素数。

平台会在计时前生成并上传输入、分配内存并执行预热。可以重点关注逐行降序排序、前缀和、合并访存，以及非 2 的幂行宽的 padding 处理。
